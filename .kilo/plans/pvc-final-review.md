# PVC 具体交割月份合约数据采集 — 审查与实施方案报告

## 一、项目概况

| 项目 | 内容 |
|------|------|
| 项目名称 | AKShare PVC 期货数据采集项目 |
| 工作目录 | /Users/johnm/Projects/akshare-futures-data |
| 当前分支 | release/pvc-nine-contracts |
| AKShare 版本 | 1.20.0 |
| Python 版本 | 3.13.3（虚拟环境 `.venv`） |
| 报告生成时间 | 2026-11-03 |

### 项目目标
在现有 AKShare PVC 行情采集项目基础上，审查增加 PVC 具体交割月份合约长期行情采集能力的可行性，并制定最小必要改动方案。

重点覆盖每年 1 月、5 月、9 月交割月份的 PVC 具体合约：
- 1 月：V2701、V2801、V2901
- 5 月：V2705、V2805
- 9 月：V2709、V2809

合约必须依据交易所实际挂牌情况动态发现，不得仅依靠预设年份和合约代码。

本阶段只进行审查、验证和方案设计，不进入代码实施阶段。

## 二、代码架构说明

### 2.1 项目结构

项目采用模块化架构，主要文件包括：

| 文件 | 说明 |
|------|------|
| `fetch_pvc.py` | 核心采集脚本，支持多合约并行采集 |
| `.github/workflows/collect.yml` | GitHub Actions 自动采集工作流 |
| `output/` | 数据存储目录，按合约代码分文件存储 |
| `tests/` | 单元测试文件 |

### 2.2 核心函数

| 函数 | 作用 |
|------|------|
| `fetch_and_update_daily_bars(symbol, session_label)` | 获取并更新日线行情 |
| `update_minute_bars(symbol, df)` | 更新分钟线行情 |
| `validate_daily_bars(df)` | 验证日线数据格式和 OHLC 逻辑 |
| `validate_minute_bars(df)` | 验证分钟线数据格式和时间戳 |
| `separate_future_timestamps(symbol, df, collected_at)` | 过滤未来时间戳异常 |
| `filter_future_anomalies(records)` | 清理历史数据中的残留异常 |

### 2.3 数据流向

```
AKShare 接口
    ↓
数据采集 (futures_zh_daily_sina / futures_zh_minute_sina)
    ↓
数据验证（validate_daily_bars / validate_minute_bars）
    ↓
异常检测与过滤（separate_future_timestamps / filter_future_anomalies）
    ↓
去重合并（records_by_key / records）
    ↓
原子写入 CSV / JSONL
```

## 五、数据质量验证

### 5.1 OHLC 关系验证
- **日线**：`high >= max(open, close, low)` 且 `low <= min(open, close, high)`
- **分钟线**：与日线相同验证逻辑

### 5.2 时间戳验证
- 日线：交易日期必须有效，不得为未来日期
- 分钟线：时间戳不得超过采集时间 + 1 分钟容差，否则标记为异常

### 5.3 成交量/持仓量验证
- 必须为非负数
- 不能为空值或负值

### 5.4 已知异常处理
系统已识别并标记以下已知异常合约：

| 合约 | 异常日期 | 异常类型 | 处理方式 |

| V2701 | 2026-12-28 | high < open | 自动删除 |
| TA0 | 2007-03-27 | high < open | 自动删除 |
| TA0 | 2007-05-11 | high < open | 自动删除 |
| TA0 | 2007-05-28 | low > open | 自动删除 |

## 六、风险与建议

### 6.1 技术风险

| 风险 | 等级 | 说明 | 缓解措施 |
|------|------|------|---------|
| 未挂牌合约 | 中 | V2801、V2805、V2809、V2901 尚未挂牌，API 返回错误 | 错误被正确捕获，不影响系统运行 |
| 数据源依赖 | 中 | 依赖 AKShare 和新浪财经接口，若接口变更可能影响采集 | 定期监控接口可用性 |
| 历史数据永久性 | 低 | 历史数据永久保留，文件会持续增长 | 定期归档或压缩历史数据 |
| 并发冲突 | 低 | 新旧分支使用不同 concurrency group，隔离良好 | 无需额外措施 |

### 6.2 改进建议

1. **增加更多合约**：当前仅覆盖 9 个主力连续合约，如需其他合约可扩展 `SYMBOL_NAME_MAP`
2. **添加监控**：建议增加采集成功率、延迟等监控指标
3. **数据归档**：历史数据文件增长较快，建议定期归档旧数据
