# PVC 数据采集质量检查清单

## 1. 合约覆盖检查

**检查内容**：需要检查合约 V0、V2701、V2705、V2709 是否全部被纳入采集范围。需要验证 ACTIVE_CONTRACTS 常量列表的位置（通常在项目根目录的配置文件中），确保包含上述四个合约代码，且格式正确（可能是列表、字典或逗号分隔的字符串）。

**验收标准**：ACTIVE_CONTRACTS 中包含 V0、V2701、V2705、V2709 这四个合约的完整代码。常量定义合理且易于维护。

**检查方法**：自动化检查脚本遍历 ACTIVE_CONTRACTS，并验证其中包含这四个合约代码；人工检查配置文件中的常量定义。

## 2. 日线、分钟线、实时快照检查

**检查内容**：三条采集流分别由什么函数负责，使用什么 AKShare/Sina 接口，以及如何验证数据是否正确写入。需要检查 daily、minute、snapshot 这三个数据流的具体实现，包括使用的 akshare/futures/sina 接口，以及写入操作的具体实现和验证逻辑。

**验收标准**：日线数据流由专用函数负责，使用 akshare 或 sina 的日线接口实现，数据写入符合预期格式。分钟线数据流由专用函数负责，使用 akshare 或 sina 的分钟线接口实现，数据写入符合预期格式。实时快照数据流由专用函数负责，使用 akshare 或 sina 的实时接口实现，数据写入符合预期格式。

**检查方法**：自动运行数据采集流程，检查每个数据流的函数调用和接口使用；人工验证采集结果的格式和写入成功标志。

## 3. 数据去重检查

**检查内容**：去重键是什么（日线：symbol+trading_date，分钟线：symbol+datetime，实时快照：symbol+source_date+source_time），以及如何验证重复运行不会产生重复记录。需要检查每个数据流的去重逻辑实现，包括去重键的定义和去重机制的实现。

**验收标准**：日线数据流去重键为 symbol+trading_date，分钟线数据流去重键为 symbol+datetime，实时快照数据流去重键为 symbol+source_date+source_time。去重机制能够有效防止重复记录的产生。

**检查方法**：自动化检查每个数据流的去重键定义；手动测试重复运行，验证数据不会产生重复记录。

## 4. 文件持久化检查

**检查内容**：每个合约的数据文件路径命名规则，以及如何验证文件是否正确创建和保存。需要检查每个合约的数据文件的完整路径命名规则，包括合约代码、日期等组成部分，以及文件验证逻辑（存在性、完整性、格式正确性等）。

**验收标准**：每个合约的数据文件路径命名规则清晰明确，包括合约代码、日期等组成部分，文件格式统一且可识别。所有合约的数据文件能够正确创建和保存，文件内容完整。

**检查方法**：自动化检查文件路径命名规则是否一致；人工或自动化验证每个合约的数据文件是否存在、内容完整及格式正确。

## 5. 异常状态检查

**检查内容**：ACTIVE/UNKNOWN/ERROR 三种状态的判定标准，以及 UNKNOWN/ERROR 合约是否允许后续重试。需要检查异常状态的定义、判定逻辑以及重试机制的实现。

**验收标准**：ACTIVE 状态表示合约正常采集中；UNKNOWN/ERROR 状态表示采集失败。UNKNOWN/ERROR 合约允许进行重试，但ERROR 合约需要更严格的验证后方可重试。

**检查方法**：自动化检查状态判定逻辑的实现；人工测试异常状态的处理流程和重试机制。

## 6. V0 回归检查

**检查内容**：如何验证 V0 原有采集逻辑、数据文件路径、字段定义和采集逻辑保持不变。需要确保 V0 版本的采集逻辑和数据存储结构保持一致，包括字段定义、数据格式和存储路径等。

**验收标准**：V0 原有采集逻辑、数据文件路径、字段定义和采集逻辑保持不变，所有字段映射和数据格式与 V0 版本保持一致。

**检查方法**：自动化检查 V0 版本的代码实现；手动或自动化比较 V0 版本的数据结构和字段定义，确保与原始版本一致。
